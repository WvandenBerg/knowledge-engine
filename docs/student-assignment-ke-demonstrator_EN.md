# Internship / Graduation Assignment

## "Making the invisible visible": a physical-digital demonstrator for a semantic knowledge network

---

### About us

TNO (or: *insert organisation name*) develops the **Knowledge Engine**, an
open-source platform for distributed data exchange. Unlike traditional
platforms, participants do not need to upload their data to a central database.
Instead, each party describes semantically what knowledge it can offer or
needs, and the Knowledge Engine automatically finds the right matches --
including intelligently combining multiple sources via a built-in reasoner.

We apply the Knowledge Engine in European research projects (Horizon Europe)
in the domains of energy, smart buildings, and logistics. The technology works,
but it is difficult to demonstrate: its power lies in the network, not in any
single screen. You cannot show semantic interoperability with a PowerPoint.

That is why we are looking for a student who can.

---

### The assignment

Design and build a **physical-digital demonstrator** that brings the Knowledge
Engine to life in a space the size of a conference room. The demonstrator
should let visitors -- from policymakers to software engineers -- *experience*
how a distributed knowledge network works in 20-40 minutes.

The core challenge: **make the digital physical.** When data flows between two
systems in the network, you should be able to *see* and *feel* it in the room.
Think light, movement, sound, tangible objects -- not dashboards.

We have developed two domain scenarios as a starting point (not a straitjacket):

**Scenario A -- "District 2030" (energy)**
A conference room becomes a neighbourhood. Each table is a stakeholder (solar
farm, heat pump, resident, energy market, grid operator). Physical sensors and
actuators on each table. LED tubes between tables light up when knowledge
flows. Colour encodes the data type; purple shows a reasoning chain.

**Scenario B -- "Mainport 2030" (logistics)**
A conference room becomes the Rotterdam port-hinterland corridor. Miniature
containers with NFC tags physically move between tables (terminal, trucker,
barge operator, shipper). LED corridors on the floor (blue = waterway,
orange = road, white = rail) show the data flow. The reasoner plans multi-modal
routes by automatically combining multiple parties.

You may take one of these scenarios as a starting point, combine them, or
design your own -- as long as it demonstrates the core values of the Knowledge
Engine.

### What you will do

Depending on your profile and programme, the emphasis shifts, but the
assignment always involves a combination of:

**Design & concept (creative focus)**
- Interaction design: how does a visitor experience the demonstrator?
- Physical computing: which physical representations make the network tangible?
- Spatial design: how do you arrange a room as a living network?
- User research: do visitors understand afterwards what the Knowledge Engine
  does, and why it differs from a central platform?

**Technology & implementation (tech focus)**
- Integration with the Knowledge Engine REST API (Python or JavaScript)
- Embedded systems: Raspberry Pi / Arduino, sensors, NFC readers,
  addressable LED strips (WS2812B)
- Network communication: multiple physical nodes collaborating in real time
- Data visualisation: live dashboard as the digital counterpart of the physical
  setup

**Always part of the assignment**
- A working prototype that we can deploy at conferences and EU project reviews
- Documentation so that we can set up, run, and maintain the demonstrator
  without you
- An evaluation: show the demonstrator to target audiences and measure whether
  the core messages come across

### About the Knowledge Engine

The Knowledge Engine is open-source software developed by TNO (*or: insert
organisation name*). Key properties:

- **Distributed**: data stays at the source; there is no central database
- **Semantic**: participants describe their data using ontologies (RDF/OWL);
  the engine matches automatically based on meaning
- **Reasoning-capable**: a built-in reasoner can combine multiple sources to
  answer questions that no single source can answer alone
- **Dynamic**: new participants are discovered automatically, without
  reconfiguration
- **Four interaction patterns**: ASK (pose a question), ANSWER (answer a
  question), POST (publish data), REACT (respond to data)

More information:
- GitHub: https://github.com/TNO/knowledge-engine *(adjust URL if needed)*
- Applications: EU projects in smart energy, smart buildings (SAREF ontology),
  and interoperable IoT systems
